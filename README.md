# МікроТік-аудит

Версія 1.1.2. Локальна read-only перевірка власного RouterOS: версія проти каталогу CVE, служби, користувачі, firewall input, індикатори з [бюлетеня MikroTik від вересня 2026](https://mikrotik.com/supportsec/september-2026-vulnerability/) і [CERT Polska](https://cert.pl/en/posts/2026/09/mikrotik-routeros-cve/).

Скрипт не змінює конфігурацію і не містить експлойтів. На пристрій іде лише фіксований набір команд читання через системний OpenSSH. Тіла скриптів і текст журналу з маршрутизатора не забираються.

## Вимоги

- Python 3.10 або новіший.
- Клієнт OpenSSH у `PATH`.
- Обліковий запис RouterOS із правами на читання перевірюваних розділів. Повний доступ не потрібен і не запитується.
- Для структурованого збору потрібен RouterOS 7.13 або новіший. Старіший реліз дає лише перевірку версії.
- Файли `mikrotik_audit.py`, `cve_catalog.py` і `cve_catalog.json` лежать в одній теці.

Залежностей поза стандартною бібліотекою Python немає.

## Запуск

```bash
python3 mikrotik_audit.py --update-cve
python3 mikrotik_audit.py --host 192.0.2.1 --user audit --known-hosts ~/.ssh/known_hosts \
  --untrusted-interface ether1 --trusted-network 192.0.2.0/24
python3 mikrotik_audit.py --offline snapshot.json --no-cve-update
```

`--host` оновлює каталог, якщо файлу немає або він старший за `--cve-max-age` днів (типово 7, межі 0…365; `0` оновлює щоразу). `--update-cve` оновлює завжди і без `--host` після запису завершує роботу. `--no-cve-update` і `--offline` мережу каталогу не чіпають.

Ключ NVD, якщо він є, читається лише зі змінної `NVD_API_KEY` і передається заголовком. У URL він не потрапляє.

| Параметр | Призначення |
|---|---|
| `--host` | Один IP або FQDN власного маршрутизатора |
| `--user` | Обліковий запис без керівних символів і login modifiers |
| `--port` | Порт SSH, типово 22 |
| `--identity` | Приватний ключ. Зашифрований ключ попередньо додати в ssh-agent |
| `--ask-password` | Пароль запитує сам OpenSSH у терміналі. У аргументи і файли він не передається |
| `--known-hosts` | Уже перевірений файл known_hosts. Автодовіра вимкнена |
| `--untrusted-interface` | WAN або гостьовий інтерфейс. Параметр повторюється. Це ім’я інтерфейсу, не назва interface list |
| `--trusted-network` | Довірений CIDR керування, IPv4 або IPv6. Параметр повторюється |
| `--timeout` | Бюджет двох SSH-сеансів, 15…600 секунд, типово 120 |
| `--max-rows` | Ліміт записів на таблицю, 1…1000 |
| `--report NEW.json` | Новий JSON-звіт. Наявний файл не перезаписується |
| `--snapshot NEW.json` | Санітизований зріз для повторного offline-аудиту |
| `--version` | Версія інструмента |

## Що збирається

Дві SSH-сесії. Перша читає версію. Друга, для RouterOS 7.13+, читає фіксований список розділів: IP-служби, користувачів і групи, SSH-ключі, інтерфейси та interface lists, порти bridge, фільтри IPv4 і IPv6, пакети, SNMP, імена скриптів і планувальника, netwatch, теми журналу, resource, RouterBOOT, DNS, MAC-server, neighbor discovery, device-mode, SSH, bandwidth-test, SOCKS, proxy, UPnP, RoMON, SMB і параметр `disable-ipv6`.

Коментарі, префікси журналу і лічильники з правил firewall відкидаються. Незнайома умова збігу зберігається: інакше умовний drop можна було б помилково вважати безумовним.

Збір обмежений часом і розміром відповіді. Повторні JSON-ключі відхиляються. Якщо версія між двома сесіями змінилась, вердикт версії не вважається підтвердженим.

## Межа SSH

Виклик іде з `shell=False` і без файлу конфігурації SSH користувача. Увімкнені `StrictHostKeyChecking=yes`, заборона agent і X11 forwarding, заборона local command і multiplexed connection. Команда після `--` є фіксованим виразом читання, а не текстом від оператора.

`:set` у цьому виразі пише лише локальні змінні сеансу RouterOS і не змінює об’єкти конфігурації.

## Каталог CVE

Файл `cve_catalog.json` лежить поруч зі скриптом. Оновлення йде з NVD CVE API 2.0, вибірка `cpe:2.3:o:mikrotik:routeros`, лише HTTPS на `services.nvd.nist.gov`. У каталог входять CPE продукту RouterOS. Апаратні рядки ігноруються.

Запис атомно замінює файл з правами `0644`. Якщо завантаження не вдалося, попередній файл лишається, а в stderr пишеться попередження. Якщо файл не читається, зокрема через права доступу, аудит продовжується на вбудованій підлозі й теж пише попередження.

### Версія

Встановлена версія має вигляд `7.4`, `7.4.0`, `7.4beta4`, `7.26rc1` і може мати канал `(stable)`, `(long-term)`, `(testing)` або `(development)`. Beta і rc менші за стабільний реліз із тими самими номерами, тож beta версії-латки ще всередині виключної верхньої межі.

Компонент CPE `update` є частиною релізу. `7.4:beta4` зберігається як `7.4.0beta4` і не збігається зі стабільною `7.4`. `*` і `-` лишають точний збіг лише для стабільної збірки. Інший токен не вгадується: умова лишається нерозібраною.

### Підлога бюлетеня 2026-10-06

Шість CVE додаються при кожному читанні. Завантажений файл може додати інші CVE і розширити діапазон, але не може оголосити `7.24.2` або `7.23.4` виправленими для CVE-2026-67278. Повна латка цього бюлетеня: `7.24.3`, `7.23.6`, `6.49.21` і новіші стабільні релізи відповідної гілки.

| CVE | Уразливі стабільні релізи |
|---|---|
| CVE-2026-67276 | з 7.9 нижче 7.23.4 і з 7.24 нижче 7.24.2 |
| CVE-2026-67277, CVE-2026-67279, CVE-2026-86060 | з 6.0 нижче 6.49.21, з 7.0 нижче 7.23.4 і з 7.24 нижче 7.24.2 |
| CVE-2026-67278 | з 7.0 нижче 7.23.6 і з 7.24 нижче 7.24.3 |
| CVE-2026-67281 | з 7.20 нижче 7.23.4 і з 7.24 нижче 7.24.2 |

Верхня межа не входить у діапазон. `7.24.2` і `7.23.4` не закривають CVE-2026-67278.

NVD не кодує гілку 7.25.0 beta. Для п’яти CVE, закритих у 7.25.0 beta 3, збірка нижче 3 вразлива, збірка 3 і вище — ні. Для CVE-2026-67278 будь-яка beta або rc 7.25.0 лишається непідтвердженою.

Якщо NVD дав лише верхню межу, старіші номери вважаються вразливими. Через це `6.49.21` може лишатися в переліку окремих CVE 2022 і 2025 років, хоча вересневий бюлетень 2026 для нього закритий.

### Коли вердикт не буває латкою

- Beta або rc поза діапазоном і поза явним правилом 7.25.0 отримує `UNKNOWN`. `7.26beta1` не дає `ROS-2026-09: PASS`.
- Обмежений діапазон разом із CPE без меж: всередині діапазону `AFFECTED`, поза ним вирішальний `UNKNOWN`. Злиття з підлогою бюлетеня цю ознаку не стирає.
- Частково нерозібраний запис поводиться так само: відома умова лишається чинною, версія поза нею є вирішальним `UNKNOWN`.
- Повністю безмежний або повністю нерозібраний CVE не перетворює кожен маршрутизатор на вразливий і потрапляє в `CVE-NO-RANGE`.
- Порожній запис без меж і діапазон, у якого нижня межа не нижча за верхню, файл каталогу відхиляє.

Каталог не доводить доступність з мережі, не замінює бюлетень, якого ще немає в NVD, і не є доказом відсутності компрометації.

## Що оцінюється локально

Після збору дані не повертаються на маршрутизатор.

- Версія проти каталогу і окремий рядок для кожного підтверджено вразливого CVE.
- Збіг версій активних пакетів і RouterBOOT.
- Активний користувач `admin`, ім’я `ops` як опублікований індикатор, група і адресний ACL користувача.
- Незашифровані служби, ACL служб відносно `--trusted-network`, сертифікат і те, чи input для порту служби може прийняти трафік з `--untrusted-interface`.
- MAC-Winbox, MAC-Telnet, MAC-ping, neighbor discovery.
- DNS recursion і перевірка сертифіката DoH.
- Bandwidth-test без автентифікації, SOCKS, proxy, UPnP, RoMON, SMB, SNMP, криптографія і forwarding SSH.
- Прапорець device-mode і теми журналу, які збігаються з опублікованими індикаторами. Сам текст журналу не читається.

Аналіз firewall навмисно неповний і обережний. Невідомий збіг або невідома дія зупиняє висновок. Умовний `accept` раніше в ланцюгу не дає вважати пізніший `drop` достатнім блокуванням. NAT, raw, mangle, маршрути і топологія не моделюються.

## Результат

Вердикт завжди частковий: `PARTIAL_WITH_FINDINGS` або `PARTIAL_NO_CONFIRMED_FINDINGS`. `PASS` стосується одного правила, не пристрою.

Код виходу складається з двох бітів. Біт 1 ставиться, якщо є `VULNERABLE_VERSION`, `MISCONFIGURATION`, `POTENTIAL_EXPOSURE` або `INDICATOR`. Біт 2 ставиться, якщо є хоч один `UNKNOWN`. Знахідка `COVERAGE-LIMIT` завжди має статус `UNKNOWN`, тому успішний запуск завершується з кодом 2. Переривання з клавіатури дає код 130. Відхилений запуск до формування звіту дає код 2 і текст `Аудит не підтверджено`.

`--report` і `--snapshot` створюють лише новий файл і не перезаписують наявний. Права цього файлу `0600`.

Консоль показує знахідки, крім `PASS`, `OBSERVED` і `NOT_APPLICABLE`. Повний перелік лишається в JSON-звіті.

## Межі

Звіт сам перелічує непокрите: CVE поза локальним каталогом, фактична доступність з Інтернету, NAT, raw, mangle, маршрути, upstream ACL, VRF і повна VLAN або bonding топологія, слабкі паролі, TLS handshake, повний аналіз скриптів, приховані сліди компрометації, Wi-Fi, VPN, RADIUS, IPv6 ND/RA і відкладене застосування `disable-ipv6`.

GitHub Actions виконує `pytest`, `ruff` і `mypy` для `cve_catalog.py` та `tests`. `mikrotik_audit.py` у крок lint і перевірки типів не входить. Окремих тестів SSH, firewall, L2 і парсера відповіді немає. Запуск на живому RouterOS або CHR у цих перевірках не виконується.

## Перевірки

```bash
python3 -m venv .venv
.venv/bin/pip install pytest ruff mypy
.venv/bin/ruff check cve_catalog.py tests
.venv/bin/mypy cve_catalog.py
.venv/bin/pytest
```

| Оновлення NVD поруч зі скриптом без звуження підлоги | `test_update_normalizes_nvd_and_paginates`, `test_narrowed_file_cannot_drop_the_floor`, `test_update_only_writes_beside_the_script` |
